1Executive Summary

GazeConnect Pro is a Windows desktop AAC application for users who communicate through eye gaze. It is not a normal CRUD app. It is a real-time human-computer interaction system with a safety-critical UI, a hardware bridge, an async Python stream processor, a dwell state machine, local TTS, offline-first word prediction, and a separate home planning module. The codebase proves that the developer can build across product, backend, algorithms, local hardware, packaging, and accessibility.

Most important implementation truth: selection is intentionally dwell-based. The user does not drag, right-click, or depend on hover-only menus. The frontend owns the user-visible dwell state machine; the backend owns gaze conditioning, classification, filtering, calibration, magnetism hints, prediction, TTS, and data services.
Clinical product Accessibility-first UI

Large targets, dark mode, Hindi + English labels, no main-screen scrolling, and emergency access from every important context.

Realtime backend Python asyncio WebSocket server

Receives gaze from a local TCP hardware bridge, processes it frame-by-frame, and broadcasts normalized gaze to React over port 8765.

Algorithms Signal processing + ML inference

Signal conditioning, I-VT fixation/saccade classification, One Euro/Kalman/OptiKey filtering, neural ONNX prediction, and safety guardrails.

Career story Backend/ML/HCI alignment

The strongest job fit is backend systems for accessibility, real-time data, ML inference, computer vision tooling, and human-computer interaction.

4End-to-End User Flow

4.1 From Eye Fixation to Button Click

  1. The Tobii ET5 observes the user's eyes and reports a gaze point through Tobii software.
  2. TobiiGazeHelper.exe receives GazePointDataMode.LightlyFiltered samples.
  3. The helper normalizes pixel coordinates and sends JSON lines to Python on TCP 5555.
  4. TobiiReceiver reads the TCP stream, converts timestamps, and emits GazePoint objects.
  5. SignalConditioner handles blink hold, tracking loss, out-of-bounds tolerance, and frozen data.
  6. GazeClassifier uses velocity thresholds and hysteresis to decide fixation/saccade/glissade.
  7. The backend applies calibration, OptiKey key zones, adaptive Kalman filtering, optional One Euro filtering, and target magnetism.
  8. The backend broadcasts the gaze payload over WebSocket.
  9. useWebSocket.tsx dispatches the gaze frame to GazeCursor.tsx.
  10. GazeCursor.tsx updates the cursor directly on the DOM hot path, finds a gaze target, starts onset, fills dwell progress, locks after 10%, and clicks when dwell completes.

4.2 From Button Click to Speech

GazeButton firesThe selected AAC tile invokes onClick.
Screen handlerThe screen calls onSpeak(text) or onNavigate(route).
TTS routerchooseSpeechRoute chooses mute, backend, or browser speech.
Backend pathEnglish text can go to Python pyttsx3 through WebSocket.
Browser pathHindi or mixed Devanagari speech uses browser SpeechSynthesis.
Double-speech fix: src/utils/ttsRouting.ts deliberately selects exactly one voice path per utterance. Hindi and Devanagari text are routed to browser speech because Windows SAPI5 may not speak Hindi reliably through pyttsx3.

4.3 From Typed Text to Predictions

  1. KeyboardScreen.tsx or SpatialKeyboardScreen.tsx sends get_predictions through useWebSocket.
  2. python/main.py calls WordPredictionEngine.predict().
  3. The engine builds candidates from prefix trie, n-grams, smart bigrams, core vocabulary, recency, patient bigrams, Hindi vocabulary, context topics, and neural fusion.
  4. Guardrails filter blocked words and phrases repeatedly before output.
  5. Sentence prediction and neural sentence continuation may add short suggestions.
  6. Local predictions return immediately. If Datamuse is enabled, a later background message may append low-score online suggestions.

5.2 GazeCursor: The Frontend Dwell Engine

GazeCursor.tsx is the central user-perceived selection engine. It subscribes to backend gaze frames, maps them into window coordinates, finds the best target, shows the cursor and progress ring, and finally triggers a click. It uses direct DOM writes on the hot path to avoid React render pressure at gaze frequency.

MechanismCurrent behavior
Target discoveryCollects data-gaze targets, refreshes snap targets, and registers targets back to the backend for magnetism.
Onset delayStarts only after a short stable acquisition window. Default authoritative onset is 250ms; browser cursor uses its own 280ms default.
Dwell progressCategory-based dwell from DwellTimeContext, plus repeat-dwell cadence on keyboard keys.
LockLocks at 10% progress. Lock-break requires enough movement and target-rect escape, reducing false aborts from ET5 noise.
Saved dwellBrief gaze loss can preserve progress only when the same DOM element is reacquired within the retention window.
TelemetryRecords dwell events, interrupts, latency, freeze events, and target geometry in gazeTelemetry.ts.

5.3 GazeButton: Accessible Target Wrapper

GazeButton.tsx standardizes large gaze-friendly buttons. It supplies data-gaze, context, custom dwell attributes, visual progress states, repeat behavior, always-active flags, and minimum accessible sizing. It does not replace GazeCursor; instead it gives GazeCursor reliable semantic targets.

5.4 Dwell Timing Authority

The single authoritative dwell table is src/config/dwellTimeConfig.ts. Current default examples include:

  • standardButton: 1300
  • navigationButton: 1400
  • keyboardKey: 1100
  • quickfire: 1000
  • medicalUrgent: 900
  • emergencyButton: 2000

This reflects a deliberate safety trade-off: emergency controls remain visually prominent and always accessible, but are not all hardcoded to 400ms because false emergency activation is a real clinical risk.

7.3 Gaze Algorithms in Plain English

Signal conditioning Decide whether a sample is usable

A blink or temporary invalid frame should not instantly reset the cursor. The conditioner holds recent valid data briefly but rejects stale or frozen input.

I-VT classifier Velocity tells intent

Slow gaze movement is treated like fixation; fast movement is treated like saccade. Hysteresis prevents rapid state flipping.

One Euro Smooth when slow, responsive when fast

The filter changes cutoff based on motion, so fixation is stable and quick eye movements are not overly delayed.

Kalman Estimate position despite noise

The adaptive Kalman filter balances predicted motion and measurement noise. The code uses different noise assumptions for fixation, saccade, and glissade.

OptiKey zones Make keyboard dwell forgiving

Key-aware damping and lock radii reduce accidental jumps between adjacent keyboard keys.

Magnetism Assist target acquisition

Registered targets let the backend gently pull toward intended controls without hiding the user's actual gaze telemetry.

The Tobii Eye Tracker 5 is accessed through a .NET bridge because the Tobii SDK is more reliable from the Windows/.NET side than directly from Python. This bridge keeps hardware concerns out of React and gives Python a simple local JSON stream.

9.2 Neural Model

The neural model is a CIFG-LSTM exported to ONNX. CIFG means the input gate is coupled to the forget gate (input = 1 - forget), reducing parameters while retaining LSTM-style sequence memory. The current training log reports 661 vocabulary items, 512 hidden size, and 1,792,917 parameters. Runtime inference uses CPU ONNX Runtime and hard timeouts: around 30ms for next-word prediction and 40ms for short sentence continuation.

9.3 Safety Guardrails

AAC prediction must never make the patient fight the system for dignity. Harmful, violent, inappropriate, or mentally harmful suggestions are filtered before display. The blocklist is exact token based, with separate phrase checks, so ordinary emotional words that the patient may need for expression are intentionally preserved.

13Backend Career Fit and Current Market Research

The career strategy should lead with Python async systems, signal processing, device integration, ONNX inference, and clinical product constraints; React/Electron should be presented as supporting evidence that you can ship the full product.

Market reality as of 2026-07-07: direct eye-tracking/AAC companies exist, but many open engineering roles are onsite or region-restricted. 14.3 Backend Interview Questions You Can Expect

QuestionHow to answer from this project
How did you handle real-time latency?Explain local-only loopback protocols, direct DOM writes for cursor, local predictions first, hard ONNX timeout, no blocking Datamuse, TTS worker thread.
Why use Python for real-time gaze?Python was enough for 33-66Hz local processing, with C# used where SDK/hardware integration demanded it. The system isolates hot paths and keeps expensive operations out of frame loops.
What does the Kalman filter do?It estimates true gaze position by combining prediction and measurement; measurement noise changes by gaze state so fixation is stable and saccade response remains fast.
What is I-VT?Velocity-threshold identification: classify eye movement based on angular velocity, with thresholds and hysteresis to avoid jitter between states.
How do you prevent unsafe predictions?Guardrail filters run across n-gram, neural, sentence, patient, and optional online paths; blocked words and phrases are removed before UI output.
How would you scale this architecture?For this product, local-first is a privacy and latency feature. For cloud scaling, separate telemetry ingestion, model training, settings sync, and crash reporting, while keeping runtime gaze local.
