TL;DR — what powers the keyboard

In one paragraph

As the patient spells a word by staring at keys (dwell), the app asks a local Python "brain" for the most likely next words. That brain is not a single model — it is a fusion of five signals: (1) n-gram word statistics, (2) smart bigrams, (3) a prefix trie for partial words, (4) per-patient personalization, and (5) a tiny trained neural network (CIFG-LSTM) that re-ranks by sentence meaning. A safety guardrail filters the result, and the top few words appear in the strip above the keyboard. Everything runs 100% offline, on-device.

Everything is local: no cloud, no internet, no data leaves the device. The suggestions the patient sees are computed by the Python backend on the same machine.

Every concept, explained simply

Read this once and the rest of the document is easy. Each card: the plain-English idea on top, the technical detail (and where it lives) underneath.

Tokenization
Cutting text into words. "how are you" → ["how","are","you"].
Lower-cased, whitespace-split. Everything downstream works on these word tokens.
Vocabulary
The fixed list of words the system "knows". The keyboard knows 2,574 words; the neural net knows a smaller 661.
ALL_VOCABULARY in word_prediction.py (keyboard); vocabulary.json (neural word↔index map).
N-gram model
Autocomplete by counting. It has read many AAC sentences and learned "which word usually follows which". Unigram = how common a word is on its own. Bigram = given the 1 previous word. Trigram = given the 2 previous words.
NGramModel(n=3) in word_prediction.py. Trained at startup from in-code corpora. The primary ranker (~0.75 weight).
Prefix trie
A tree that instantly lists every known word starting with the letters typed so far — like a phone book sorted by first letters. Type "he" → help, hello, her…
PrefixTrie in word_prediction.py, built over the 2,574-word vocabulary and shared with the n-gram model.
Smart bigrams
A hand-picked, pre-computed table of the strongest "word A → word B" pairs. Sharper than raw counts for the words patients actually use.
python/data/smart_bigrams.json — 1,339 pairs / 378 context words, loaded fully into the n-gram model at startup.
Embedding
Turning a word into a list of numbers so a neural net can do math on meaning — like giving every word GPS coordinates in a "meaning space" where similar words sit close together.
A 128-dimension vector per word. First layer of the neural model (Embedding(128)).
LSTM
A neural network that reads words one at a time and remembers context as it goes — a reader with short-term memory, so it "gets" the sentence, not just the last word.
Long Short-Term Memory recurrent net, 512 hidden units. The core of the model.
CIFG-LSTM
A leaner LSTM. A normal LSTM has 3 "gates"; this one couples two of them, cutting size ~25% for the same job — perfect for a small, fast, medical-grade app.
Coupled Input-Forget Gate LSTM: input_gate = 1 − forget_gate. CIFGLSTMCell in ml/model.py.
Softmax
Turns the net's raw scores into probabilities that add up to 100% — "how likely is each possible next word".
Final activation over the 661-word output layer.
Quantization
Shrinking the model by storing its numbers as small whole numbers instead of big decimals — ~4× smaller with almost no quality loss. That's why the model is 1.81 MB, not ~7 MB.
Dynamic int8 quantization at export → gazeconnect_lm_quantized.onnx.
ONNX & onnxruntime
ONNX is a portable model file; onnxruntime is the small engine that runs it. Train once (in PyTorch), ship the .onnx, and it runs the same on every machine — no PyTorch needed to run.
The app ships onnxruntime (~34 MB, CPU). No torch at run time.
Fusion
Blending the n-gram guess and the neural guess into one ranked list — statistics for speed, neural for meaning. Neither one wins alone.
PredictionFusion in ml/fusion.py (formula below).
Personalization
The app remembers the patient's own words and phrasing and ranks them first — the more Papa types, the more it sounds like Papa.
RecencyTracker + PatientBigramTracker + custom dictionary, persisted under data/patient_data/.
Guardrails
A safety net that removes harmful/inappropriate words from suggestions on every path, in English and Hindi/Hinglish — nothing blocked ever appears.
prediction_guardrails.py, applied last, always.
Dwell (how you "click")
The patient selects a key or suggestion by looking at it steadily for a moment. There is no mouse — the eyes are the pointer.
Dwell selection in the gaze pipeline; a chosen suggestion is inserted and fed back into learning.
WebSocket (the pipe)
An always-open two-way phone line between the on-screen keyboard and the Python brain, so suggestions come back instantly as you type.
ws://127.0.0.1:8765, served by python/main.py.
Abbreviation expansion
Short codes expand to full words/phrases (e.g. common shortcuts) so the patient types fewer letters.
ABBREVIATIONS + custom abbreviations loaded at runtime, checked first in predict().

System design — the whole picture

Three processes cooperate. The UI never predicts; it asks the Python backend over a local WebSocket. The backend runs the entire engine and returns ranked words. The eye tracker only supplies gaze.

Frontend (Electron/React) Backend (Python) Neural (ONNX) Data & model files Safety

The eye tracker (.NET TobiiGazeHelper, Windows-only) feeds gaze to the same backend on TCP 5555; it decides which key/suggestion the eyes select, but it is not part of the word-prediction math.

Real-time flow — one keystroke → suggestions

  1. Type — the patient dwells on a key; KeyboardScreen.tsx appends the character to its text state.
  2. Emit — useWebSocket.tsx sends update_text (for the session log) and get_predictions { text, top_k:12, lang } over the WebSocket.
  3. Route — main.py receives it and calls _get_predictions(), which calls WordPredictionEngine.predict(text, top_k).
  4. Predict — the engine runs the 5-layer pipeline (below): abbreviation → n-gram+trie+bigrams → personalization → neural fusion → guardrails.
  5. Reply — the backend sends a predictions message: { words:[{word,score,source}], sentences:[…] }.
  6. Render — the client updates state; KeyboardScreen.tsx shows the top suggestions. Dwelling one inserts it, and the accepted word feeds back into learning.
The neural step has a hard 30 ms timeout and never runs on the gaze path — if it's slow it silently falls back to n-gram, so the 66 Hz eye-tracking loop is never blocked.

The prediction pipeline — how candidates are ranked

Five cooperating signals, blended by interpolation, boosted for the individual patient, filtered for safety.

Fusion formula (how n-gram and neural combine)

P_final(word) = λ_ngram · P_ngram(word)  +  λ_nn · P_neural(word) # λ_ngram is primary (default ≈ 0.75, clamped 0.50–0.90) — statistics carry the base # λ_nn is the neural weight (clamped 0.10–0.50) — semantic re-ranking, not the base # +15% "agreement bonus" when both n-gram AND neural rank the same word # patient-learned words get a history boost (×1.8), ranking highest overall # a neural-only word must exist in the 2,574-word ALL_VOCABULARY to survive # finally: guardrails drop any blocked word
① Abbreviation expansion
If the typed token is a known short code, expand it to the full word/phrase first. ABBREVIATIONS + custom.
▼
② N-gram + prefix trie primary
Generate candidates: trie completes the partial word, n-gram + smart bigrams score "next word given context". This is the base ranking (~0.75).
▼
③ Patient personalization
Boost the patient's own words: recency (30-day window), patient bigrams, custom dictionary. Learned words get ×1.8–3 and rank highest.
▼  neural re-rank
④ Neural fusion (CIFG-LSTM)
fusion.py blends the neural next-word probabilities into the n-gram scores using the formula above — semantic context the statistics miss. 30 ms timeout → fallback.
▼
⑤ Safety guardrails (always last)
Drop any blocked word (English + Hindi/Hinglish). prediction_guardrails.py — nothing blocked ever surfaces.
▼  top-4 words + sentence strip → UI

Why fusion, not "just the neural net"?

The n-gram engine is fast, deterministic, and knows all 2,574 words. The neural net is smarter about meaning but only knows 661 words. Using statistics as the base and the neural net as a re-ranker gives the best of both — and if the neural step ever stalls, statistics still answer instantly.

Why the patient always wins

Personalization boosts are applied with a max() guard so a patient-learned word can only rise, never be buried by a generic prediction. The more Papa types, the more the suggestions sound like Papa.

How the Python scripts connect (the dots)

At startup (once)

WordPredictionEngine.__init__ wires everything together:

  • builds NGramModel(n=3) and trains it on the in-code AAC corpora;
  • loads smart_bigrams.json into the n-gram model;
  • builds the PrefixTrie over the 2,574-word ALL_VOCABULARY;
  • creates RecencyTracker + PatientBigramTracker (reads patient_data/);
  • lazily creates PredictionFusion → which creates NeuralPredictor → which loads gazeconnect_lm_quantized.onnx + vocabulary.json via onnxruntime.

Per keystroke (real time)

KeyboardScreen.tsx → useWebSocket.tsx → main.py _get_predictions() → WordPredictionEngine.predict() → (abbrev → n-gram/trie/bigrams → personalization → fusion.py calls inference.py → onnxruntime runs the .onnx) → prediction_guardrails.py → top-4 → back over the WebSocket → UI.

Offline — the training side (only when deliberately improving the model)

aac_corpus.py (curated AAC sentences) + optional fetch_external_corpus.py (a small slice of real Tatoeba English) build one training corpus → train.py trains the network defined in model.py (CIFGLSTMCell), using vocabulary.py + dataset.py → exports to ONNX and int8-quantizes → writes gazeconnect_lm_quantized.onnx + vocabulary.json. verify_model.py health-checks it. The new .onnx is committed to git, so it flows to every environment and into the installer.

Train once → benefit everywhere. Retraining is not a per-session step. Run retrain-model.sh (Mac, GPU) / retrain-model.bat (Windows) only to change the model, then commit the new file.

The trained neural model (the .onnx) — deep dive

What it is

A small on-device neural language model — a "mini NLM", not a large LLM. It adds semantic understanding of context that pure n-gram statistics can't.

Type
CIFG-LSTM (Coupled Input-Forget Gate LSTM)
Shape
Embedding(128) → CIFG-LSTM(512) → Dropout(0.2) → Linear → Softmax
Params
~1.79 M
File / size
gazeconnect_lm_quantized.onnx · 1.81 MB (1,897,931 bytes)
Vocab
661 words
Runtime
onnxruntime (CPU) — no torch at run time

Reading it left-to-right (simple)

Embedding(128) — each word becomes 128 numbers (its "meaning coordinates"). CIFG-LSTM(512) — reads the words in order, keeping a 512-number memory of the sentence so far. Linear → Softmax — turns that memory into a probability for every one of the 661 words: "what comes next?". The engine takes those probabilities and blends them into the n-gram ranking.

Not Gboard-level — it is far smaller than Google's models. The lean path to better quality is to retrain this same model bigger (larger vocab + richer data), never to add a heavy LLM.

The prediction "brain" is tiny; the footprint is fixed runtimes. The heavy general LLM (~300 MB + 0.5–1 GB RAM) is opt-in and never in the installer — deliberately, for low-spec offline machines.

Design decisions & rationale

  • Dev–prod parity is a hard rule. ONE model artifact is identical across Mac-dev, Windows-dev, and the shipped installer — what a developer tests is exactly what the patient gets.
  • No general-purpose LLM in the default app. SmolLM2-360M / onnxruntime-genai are memory-heavy (~0.5–1 GB RAM) and unsafe for low-spec offline machines. They stay opt-in only, never bundled.
  • Fusion, not replacement. N-gram statistics are the fast, complete base; the CIFG-LSTM only re-ranks. If the neural step stalls, statistics still answer instantly (30 ms timeout).
  • Bigger model = same model retrained. The lean path to more quality is a larger-vocab retrain of this CIFG-LSTM (real-corpus pipeline is built), not a heavy LLM.
  • Safety is non-negotiable. Guardrails run last on every path, in English and Hindi/Hinglish.
  • Installer actually bundles the model (--add-data + --collect-all onnxruntime) so the neural layer reaches end users — verify the packaged log shows [Neural LM] Loaded.
